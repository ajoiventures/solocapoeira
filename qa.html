Visual Consistency
0/0
✓
Spacing follows an 8px grid
All padding and margin values are multiples of 4px or 8px. No arbitrary values like 11px or 17px.
P1
✓
Type hierarchy is clear (max 3 sizes per screen)
Heading, body, caption. More than 3 type sizes on one screen = visual noise. Check font-size values across each page.
P1
✓
Color usage is intentional — every color has a meaning
Red = danger/error. Green = success/progress. Gold = achievement/XP. Blue = info/navigation. Orange = warning/secondary. No decorative color that contradicts these.
P1
✓
Light mode and dark mode both look intentional
Toggle both themes on every major screen. Shadows may need inverting. Border colors need adjusting. Images need dark/light variants if they use transparency.
P1
✓
Border radius is consistent across component types
Cards all use the same radius. Buttons all use the same radius. Chips all use the same radius. Mixing 6px / 8px / 10px randomly feels broken.
P2
✓
Icon sizes are consistent within context
Navigation icons all the same size. In-line icons match the line-height. Action icons (buttons) all the same size. No random 14px / 18px / 22px mix.
P2
✓
Loading states exist for every async operation
Skeleton screens, spinners, or disabled states on every button/card that triggers async work. Never leave the user staring at a frozen screen.

Interaction Quality
0/0
✓
Every interactive element has a hover state
Buttons, links, cards with onclick, list items. If it does something, it must look different on hover. Users scan for affordance.
P1
✓
Every button shows feedback within 100ms of tap
Visual press state (scale, darken, or ripple). No "dead" tap — user must know the system received their input immediately. 100ms is the threshold for feeling instant.
P0
✓
Destructive actions require confirmation
Delete, reset, log out. Two-step: tap → confirm → execute. No single-tap irreversible actions. The confirmation must name what will be lost.
P0
✓
Animations serve purpose — not decoration
Page transitions orient the user (forward/back). Progress animations show real state. Celebration animations are earned. Nothing animates just because it can.
P2
✓
All animations respect prefers-reduced-motion
@media (prefers-reduced-motion: reduce) disables or reduces all CSS animations and transitions. Check in DevTools → Rendering → Emulate prefers-reduced-motion.
P1
✓
Toast / notification dismissal works correctly
Auto-dismiss after set time. Manual dismiss always available (× button). New toast doesn't stack infinitely. Queue clears properly when navigating away.
P1
✓
Navigation back always works and goes to the right place
Back button/gesture returns to the logical previous screen. Tap-to-detail → back → same scroll position in list. No "back" that dumps user at root.
P0
✓
Swipe gestures (if any) have visible affordance
Users don't discover swipe gestures unless hinted. Show a peek of the next item, a drag handle, or an onboarding hint on first use.

Mobile & Responsive
0/0
✓
All tap targets are minimum 44×44px
Apple HIG minimum. Use DevTools → Inspect to check computed size. Tiny close buttons, small checkboxes, and icon-only links are common failures. Add padding, not size.
P0
✓
Nothing overflows horizontally on 375px width (iPhone SE)
The minimum viable mobile viewport. DevTools → Dimensions → 375×667. Horizontal scrollbar = fail. Check all pages. Long strings, wide tables, and inline-flex rows are common culprits.
P0
✓
Bottom navigation is above the iOS home indicator
iPhone X and later: add padding-bottom: env(safe-area-inset-bottom) to fixed bottom bars. Otherwise elements are hidden behind the home indicator swipe zone.
P0
✓
Keyboard doesn't obscure focused inputs
On mobile, the virtual keyboard covers ~40% of screen. Test every input field: when keyboard opens, the focused field must scroll into view. Use scrollIntoView() if needed.
P0
✓
Correct input types trigger the right keyboard
type="number" → numeric keyboard. type="email" → @ keyboard. type="tel" → phone keyboard. inputmode="decimal" for decimals. Wrong keyboard = massive UX friction.
P1
✓
App works in landscape orientation
Rotate to landscape. No broken layouts, hidden navigation, or unscrollable content. Modals and fixed elements must adapt. Particularly important for timer and video screens.
P2
✓
PWA install prompt and icon are configured
manifest.json: name, short_name, icons (192px + 512px), theme_color, background_color, display: standalone. Test "Add to Home Screen" on both iOS and Android.

Accessibility
0/0
✓
Text contrast meets WCAG AA (4.5:1 for body text)
Use Chrome DevTools → Inspect element → Color swatch shows contrast ratio. All body text must pass 4.5:1. Large text (18px+) must pass 3:1. Most common failure: grey text on white/light background.
P0
✓
All images have descriptive alt text
Decorative images: alt="". Informative images: describe what the image shows. Icon buttons: aria-label="Close". Never alt="image" or missing alt.
P0
✓
All interactive elements are keyboard reachable
Tab through the entire page. Every button, link, input must be reachable and operable with keyboard only. Custom interactive elements need tabindex="0" and keydown handlers.
P1
✓
Focus indicator is visible on all interactive elements
Never outline: none without a custom focus style. The focus ring must be clearly visible. Test with Tab key — can you tell where focus is at all times?
P1
✓
Color is never the only way information is conveyed
Red error state must also have an icon or text label. Green success must also have a checkmark or "Success" text. ~8% of men have color vision deficiency.
P1
✓
Form inputs have associated labels (not just placeholders)
Placeholder disappears when user types. Labels must persist. Use <label for="id"> or aria-label. Screen readers and autofill both depend on proper labels.
P1
✓
axe DevTools scan returns zero critical violations
Install axe DevTools browser extension. Run on every major page. Fix all Critical and Serious violations before shipping. Best automated check available.

Performance
0/0
✓
LCP (Largest Contentful Paint) under 2.5s on mobile
Run Lighthouse in Chrome DevTools → Mobile preset. LCP <2.5s = Good. 2.5–4s = Needs improvement. >4s = Poor. Main causes: large images, render-blocking JS, slow server.
P0
✓
JS bundle under 200KB gzipped
Run npm run build and check dist/ file sizes. Or use npx vite-bundle-visualizer. Over 200KB = audit imports. Common offenders: moment.js, lodash (use tree-shakeable alternatives).
P1
✓
Heavy list views use windowing / virtual scroll
Any list over 50 items should render only visible items. 249 movement cards rendering fully = 249 DOM nodes, 249 event listeners. Use react-window or custom offsetTop calculation.
P1
✓
Images are correctly sized and use modern formats
WebP or AVIF over PNG/JPEG. Serve at display size (no 2000px image in a 200px slot). Use loading="lazy" on below-fold images. Use width and height attributes to prevent layout shift.
P1
✓
No unnecessary re-renders on state changes
React DevTools → Profiler → record a rep log action. Only the changed component and its direct children should re-render. Add React.memo, useMemo, useCallback where profiler shows excess renders.
P2
✓
App works fully offline (PWA / service worker)
DevTools → Network → Offline. Core features must work. Training logging, viewing movements, checking progress — all must work without connection. Only sync operations should fail gracefully.

Error States & Edge Cases
0/0
✓
Error messages tell the user what to do — not what went wrong
"Error 403" → bad. "You don't have permission to do this. Contact support at help@app.com" → good. Every error message answers: what happened? what can I do now?
P0
✓
App doesn't crash on corrupted localStorage data
Open DevTools → Application → Local Storage → manually corrupt a value (set a number field to "hello"). Reload. The app must recover gracefully, not white-screen. Test with JSON.parse try/catch.
P0
✓
Network failures show a useful message (not a spinner forever)
DevTools → Network → Offline → trigger any fetch. After 5s of no response, show "Check your connection and try again" with a Retry button. Never spin forever.
P0
✓
localStorage quota exceeded is handled gracefully
Browsers limit localStorage to 5–10MB. When full, setItem throws a QuotaExceededError. Wrap all writes in try/catch. Show "Storage full — export your data" message, not a silent crash.
P1
✓
404 / unknown route has a designed page
Navigate to a nonexistent route. Must show a helpful page: "This page doesn't exist" + a link back to home. Not a blank screen or React error boundary dump.
P1
✓
Brand new user (zero data) sees a useful first screen
Clear localStorage entirely. Reload. Every page must have a designed Day 0 state. No "undefined" values, no empty arrays crashing .map(), no NaN/0% stats without context.
P0
✓
Power user (max data) sees no performance or layout issues
Seed 10,000 rep entries, 200 session logs, all movements at Instinct. Reload. Check: page load time, scroll performance, layout integrity. High data = stress test for every list, chart, and stat.
